# R11 — Gate 2 복구: 같은 체크포인트에서 256과 512를 둘 다 잰다

> **사전등록 문서다. 결과를 보기 전에 커밋한다.**
> 이 문서가 커밋되기 전에는 R11 세션을 돌리지 않는다. 사후에 기준을 만들지 않는다.

작성 2026-08-09 · 브랜치 `r121-intake-and-cleanup`

---

## 0. 왜 이 실험이 필요한가 — 게이트가 자기 정의를 안 지켰다

Gate 2 정본(`paper/full/notes/긴_논문_개선해야할점.md:171-178`)의 **첫 조항**:

> - **같은 checkpoints**를 512 tokens 이상으로 재평가한다.

`_env76_max512`(512 감사)는 그걸 만족하지 않는다. `src/make_nb_r5.py:168-169`가 사실을
적어 두었다:

> ⚠️ **BATCH 1의 arm1/2/3 round-3 체크포인트는 이미 삭제됐다.** 따라서 512-token 평가 전에
> 세 arm을 동일한 데이터·하이퍼파라미터로 round 1→3까지 **다시 학습한다.**

`tasks/todo.md`의 Gate 2 체크리스트에 **체크포인트 동일성 항목이 없어서** ✅로 통과했다.
R10b(2026-08-09)가 같은 검사를 R10 코호트에 돌리다가 8B에서도 같은 일이 있었음을 드러냈다.

### 0.1 재학습이 재현되지 않는다는 증거

`results/ckpt_identity_audit.json` (`src/check_ckpt_identity.py`). 생성은
`temperature=0.0` 그리디다(`src/eval_refusal.py`).

| | `too_short` 256 → 512 | 256 미도달 응답 중 바이트 동일 |
|---|---|---:|
| **arm0** (어댑터 없음 = 재학습 없음) | 130 → **130** / 104 → **104** | **303/303 · 294/294 = 100.0%** |
| arm1 / arm2 / arm3 (`none`) | 178→74 / 229→125 / 100→48 | 23.8% / 20.3% / 35.8% |

**arm0가 100%**이므로 상한을 256→512로 바꾸는 것 **자체는** 출력을 한 글자도 움직이지
않는다. 학습 arm의 불일치는 **가중치 차이로 귀속된다.** `too_short`(40자 미만)는 상한을
올려서 바뀔 수 있는 값이 아닌데 절반으로 떨어진다.

교훈 20(`R3_STATUS.md:696`)이 이미 *"같은 시드가 같은 모델을 주지 않는다"* 라고 적어
두었다. **512 감사에만 적용되지 않았다.**

### 0.2 무엇이 걸려 있는가

그 512 감사가 `paper/flmsec/main.tex`의 **헤드라인 규약 선언**(*"Truncation-included values
are the headline throughout this paper"*)의 **유일한 근거**다. 즉 논문 전체를 어느 절단
모드로 읽을지가 이 한 코호트에 달려 있다.

⚠️ **무너진 것과 서 있는 것을 구분한다:**

| | 상태 |
|---|---|
| 512 코호트 **내부** 측정(0.72% 상한 도달 vs 169 flagged, arm 차등 EOS) | **그대로 선다.** 교차 체크포인트가 아니다 |
| 그것을 **256 헤드라인 격자로 옮기는 것** | **체크포인트 경계를 넘는 추론이다** |
| 결론의 독립 근거 | R10b가 1B에서 LoRA·full 양쪽으로 **문중 EOS arm 차등을 재현**했다 |

⇒ 원고는 규약을 유지하되 경계를 공시했다(2026-08-09). **R11은 그 공시를 걷어내거나,
아니면 규약을 바꾼다.** 어느 쪽이든 결과다.

## 1. ★ 설계를 지배하는 제약 — 한 세션 안에서 끝나야 한다

세션이 끊기면 `/kaggle/tmp/ckpt`가 죽고 **고치려는 그 버그를 그대로 재생산한다.**
Kaggle 9h(32,400s)가 설계를 정한다.

### 1.1 실측 비용 (플래너 추정이 아니라 로그에서 뽑았다)

| 측정 | 출처 | 값 |
|---|---|---|
| 8B 학습 3라운드 | `runs/r5/batch_1.log` arm1 4616.7→6574.7s · arm2 11431.2→13435.7s | ≈2,000s/arm |
| 8B 렌즈당 생성 @256 | `runs/r5/batch6.log` arm2 4렌즈 2097.0→6158.8s | **1,015s** |
| 8B 렌즈당 생성 @512 | `runs/r5/batch_1.log` arm2 2렌즈 13473.9→16953.5s | **1,740s** |
| 페르소나 arm @512 | 같은 로그 arm1 2렌즈 6615.7→11395.3s | **2,390s** |

⇒ **512는 256의 약 1.71배다.** `make_nb_r5.py` 플래너의 "렌즈당 1,800초 고정"은 512를
과소평가한다(BATCH 1이 추정 6h00m 대비 실제 **6h32m**이었다).

### 1.2 설계

| 항목 | 값 |
|---|---|
| 모델 | `unsloth/Meta-Llama-3.1-8B-Instruct` (8B 본 결과와 동일) |
| arm | **arm1 · arm3** |
| 시드 | **42** |
| 렌즈 | **`none`, `agreeable`** 2개 |
| 상한 | **같은 체크포인트에서 256과 512를 둘 다 생성** |
| 데이터 | 기존 arm1·arm3 라운드 데이터. **재생성하지 않는다** |
| 출력 접미사 | `_r11_same_ckpt_256` · `_r11_same_ckpt_512` |
| 노트북 | `nb_r11.ipynb` — `src/make_nb_r11.py`가 생성한다. **직접 편집 금지** |

**arm0를 돌지 않는 이유**: 학습이 없어 두 상한 파일이 이미 있고 **바이트 동일 100%**로
검증됐다(§0.1). 다시 재는 것은 같은 값을 다시 얻는 일이다.
**arm2를 돌지 않는 이유**: `main.tex`의 arm-차등 문장에서 0.96% 바닥값일 뿐이고, 무학습
바닥은 arm0가 이미 준다. 넣으면 +2h40m이라 §1.3의 여유를 먹는다.

### 1.3 예산 (페르소나 arm은 2,500s/렌즈@512 · 1,460s/렌즈@256로 보수적 적용)

| 구간 | 초 |
|---|---:|
| 설치·모델 다운로드 | 300 |
| arm1: 학습 3라운드 / eval @256(2렌즈) / eval @512(2렌즈) | 2,000 / 2,920 / 5,000 |
| arm3: 학습 3라운드 / eval @256(2렌즈) / eval @512(2렌즈) | 2,050 / 2,920 / 5,000 |
| 구간 오버헤드 ~40s×8 · snap · 어댑터 업로드 | 700 |
| **합계** | **20,890s = 5h48m** — 여유 **3h12m** |

**왜 렌즈를 늘리지 않는가**: 4렌즈면 학습 4,050 + @512 20,000 + @256 11,680 + 오버헤드
= **36,530s = 10h09m > 9h**. 3렌즈도 7h57m으로 여유가 1h뿐이다. **세션 초과는 부분 실패가
아니라 전손이다.**

⚠️ 렌즈 2개는 `R10_UPDATE_METHOD.md` §8.2의 *"렌즈를 2개로 줄이지 않는다"* 와 어긋난다.
**의도적이다.** 그쪽 이유는 `cohort_signature`가 `lenses`를 대조해 다른 코호트와 결합이
불가능해진다는 것인데, **R11은 방법론 코호트이고 어떤 코호트와도 결합하지 않는다.**
⇒ **결합 금지를 여기 못박는다.** `_r11_same_ckpt_*`를 `--baseline_suffix`로 쓰거나 다른
코호트의 격자에 합치지 않는다. 읽는 방법은 **자기 안에서 256 대 512**뿐이다.

### 1.4 ★ 실행 순서 — arm 단위로 완결한다

```
arm1: 학습 r1→r3 → eval @256 → eval @512 → 어댑터 보존 → snap()
arm3: 학습 r1→r3 → eval @256 → eval @512 → 어댑터 보존 → snap()
```

arm3에서 죽어도 **arm1의 쌍은 온전하고 그 자체로 유효한 within-checkpoint 비교**다.
두 arm의 256을 먼저 몰아 돌면 죽었을 때 쌍이 하나도 안 남는다.
두 eval은 같은 디스크 경로(`/kaggle/tmp/ckpt/armX_r3_s42`)를 읽으므로 같은 가중치다.

## 2. 판정 — 결과를 보기 전에 정한다

읽는 순서:

### 2.1 성립 조건 — 먼저 이것부터 본다

**같은 arm의 256 산출물과 512 산출물의 `ckpt_fingerprint.sha256`이 같아야 한다.**
다르면 세션이 중간에 끊긴 것이고, **그 arm의 결과를 버리고 다시 돈다.** 해석하지 않는다.
이 검사가 실험 전체의 성립 조건이다.

### 2.2 1차 판정 — 상한 도달이 무너지는가

`finish_reason == "max_new_tokens"`의 비율을 256과 512에서 나란히 놓는다. R74가 8B에서 본
값은 512에서 **0.72%**였다.

### 2.3 2차 판정 — 문중 EOS의 arm 차등이 남는가

`coherence_audit.incomplete_eos`. 원고 §"What the cap was hiding"이 딛는 대비는
**arm1과 arm3 사이의 서열**과 arm0(0%)와의 비중첩이다. arm0는 §0.1에서 이미 잰 값을 쓴다.

### 2.4 처분표 — 어느 쪽이든 결과로 보고한다

| 같은 체크포인트에서 512가 보이는 것 | 처분 |
|---|---|
| **(A)** 상한 도달이 무너지고(≈1%) 문중 EOS가 남으며 arm 차등 유지 | **헤드라인 규약 확정.** `main.tex`의 한계 문단(*"Two things bound this…"*)을 걷고 Gate 2를 ✅로 복원. `tasks/todo.md` 체크리스트의 다섯째 항목이 ✅가 된다 |
| **(B)** 상한 도달은 무너지는데 **arm 차등이 사라진다** | 문중 EOS의 "결과" 지위가 흔들린다. **상·하한 쌍으로 복귀**하고 included-헤드라인을 쓰는 6개 지점을 되돌린다(`analyze_dual_primary.py` 머리말·정의, `NUMBERS.md`, `main.tex` 3곳) |
| **(C)** 512에서도 상한 도달이 여전히 많다 | 8B에서도 **상한 의존성을 결과로 보고**한다. R10의 처분(`R10_UPDATE_METHOD.md` §9.3)과 같다. **1024로 올리지 않는다** |

⚠️ **눈금을 결과 뒤에 만들지 않는다.** (A)와 (C)를 가르는 선은 R74가 이미 쓴 *"R74 수준
(1% 안팎)"* 이고, R10b가 그 선을 실제로 적용했다(4.2~4.6%는 **아니다**로 판정).

⚠️ **256 헤드라인 격자는 어느 경우에도 이 코호트로 교체하지 않는다.** R11은 시드 42 ·
2렌즈 · 2 arm이다. 정본 격자는 `_env76`(3시드 · 4렌즈 · 4 arm) 그대로다. R11이 바꾸는 것은
**그 격자를 어느 절단 모드로 읽는가**뿐이다.

## 3. 이 실험이 열지 **않는** 것

- **Gate 3·Gate 4와 무관하다.** Gate 4는 model 축 전멸로 닫힘 확정이고, Gate 3은 R12와
  arm6/arm7이 맡는다
- **새 주장을 더하지 않는다.** R11은 이미 하고 있는 주장의 **근거를 고칠 뿐**이다
- (A)가 나와도 `replicated beyond one recipe` 같은 금지 문구는 그대로 금지다

## 4. 구현 메모

- 노트북 생성기는 `src/make_nb_r*.py` 패턴을 따른다: `nb_r5.ipynb`의 검증된 셀을 상속하고
  **명시적인 강제 실패 패치**로 상수만 바꾼다
- **한 arm의 두 eval은 같은 `--model_path`를 두 번 읽는다.** `--out_suffix`와
  `--max_new_tokens`만 바꾼다. 그 사이에 학습을 끼워 넣지 않는다
- **`--save_adapter_dir`로 라운드별 어댑터를 남긴다**(`src/train_round.py`, 2026-08-09 신설).
  r=16 · 7 target module · 8B(32층) ⇒ 약 **84MB/라운드**, 3라운드 = **≈250MB/arm**.
  머지는 되돌릴 수 없고 세션이 끝나면 체크포인트가 사라지므로, **이걸 남기지 않는 것이
  이 사고의 원인이었다**
- **`configs/arms.json`의 `nb_revisions`에 `nb_r11`을 추가하고 리비전을 올린다** —
  Kaggle Dataset을 New Version으로 재업로드하지 않으면 리비전 게이트가 13초에 죽인다
- 인수: `src/intake_results.py --zip <zip> --expect_max_new_tokens 256` 과 `... 512`
  **두 번** 돌린다(같은 zip). 지문 대조는 `_check_ckpt_fingerprint`가 자동으로 한다

**🛑 회귀검사**: `eval_refusal.py`에 `ckpt_fingerprint`를, `train_round.py`에
`--save_adapter_dir`를 추가한 뒤 **기존 키가 전부 불변**인지 확인한다. 옛 결과 JSON은
필드가 없으므로 인수 검사에서 `WARN`으로 강등되고 **막지 않는다**(R61 D3 · R74 선례).

## 5. 이 문서가 남기는 절차 — 다음에 또 안 겪으려면

1. **재평가는 재학습이 아니다.** 상한·렌즈·평가지표를 바꾸는 모든 재측정은 **원래
   체크포인트**에서 해야 한다. 못 하면 그 사실을 결과에 적는다
2. **어댑터를 버리지 않는다.** 머지 전에 남긴다. 수백 MB가 재학습 몇 시간과 해석 불가능한
   교란을 산다
3. **가중치 신원을 산출물에 넣는다.** `model_path`는 신원이 아니다 —
   `/kaggle/tmp/ckpt/arm1_r3_s42`는 세션마다 재학습돼도 문자열이 같다
4. **게이트 체크리스트는 정의의 모든 조항을 항목으로 갖는다.** Gate 2가 ✅로 통과한 것은
   체크리스트에 첫 조항이 아예 없었기 때문이다

## 6. 결과와 판정 (2026-08-09, BATCH 1 완료 후 기록)

§2의 순서를 그대로 밟았다. 산출: `results/r11_same_ckpt_judgment.json`
(`src/analyze_r11.py`). 절단 분해는 `intake_results.describe_truncation`과 **같은 정의**를
쓴다 — 검증으로, 같은 코드가 `_env76_max512` 8셀에서 원고의 **169 flagged / 18 hit_cap
(0.72%)** 을 정확히 재현한다.

### 6.1 성립 조건 (§2.1) — ✅ 통과

| arm | `ckpt_fingerprint.sha256` @256 | @512 | 같은가 |
|---|---|---|---|
| arm1 | `739b458578f9240d…` | `739b458578f9240d…` | ✅ |
| arm3 | `9be380d4fb86e319…` | `9be380d4fb86e319…` | ✅ |

arm1 ≠ arm3이므로 지문에 **구별력이 있다**(같은 값이 나오는 상수가 아니다). 세션이 끊기지
않았고 두 상한이 같은 가중치에서 나왔다. **Gate 2 정의의 첫 조항이 처음으로 실제 충족됐다.**

### 6.2 1차 판정 (§2.2) — 상한 도달: **(C)**

같은 체크포인트, 상한만 바뀐다. n=313/셀.

| 셀 | `hit_cap` @256 | @512 | (참조) 재학습 코호트 @512 |
|---|---:|---:|---:|
| arm1 / `none` | 1.28% | **0.00%** | 0.00% |
| arm1 / `agreeable` | 21.41% | **5.11%** | 0.96% |
| arm3 / `none` | 0.64% | **0.00%** | 0.00% |
| arm3 / `agreeable` | 28.75% | **3.83%** | 0.32% |
| **4셀 합** | 163/1252 = 13.02% | **28/1252 = 2.24%** | 4/1252 = 0.32% |

크게 떨어졌지만 **R74 수준(1% 안팎)으로 무너지지는 않았다.** 순응 렌즈 두 셀이 3.8~5.1%로,
`R10_UPDATE_METHOD.md` §9가 *"아니다"* 로 판정한 4.2~4.6%와 같은 대역이다. §2.4의 ⚠️가
정한 눈금을 그대로 적용한다 ⇒ **처분 (C): 8B에서도 상한 의존성을 결과로 보고한다.
1024로 올리지 않는다.**

⚠️ **재학습이 상한 도달을 ~7배 과소평가했다.** 같은 4셀에서 재학습 코호트는 4건, 같은
체크포인트는 28건이다. 원고의 `0.72%`는 그 코호트의 성질이지 헤드라인 격자 체크포인트의
성질이 아니다.

### 6.3 2차 판정 (§2.3) — 문중 EOS의 arm 차등: **남는다 ⇒ (B) 불발**

`agreeable` 렌즈, 512, 휴리스틱 절단 중 상한 미도달:

| arm | 문중 EOS @512 | 출처 |
|---|---:|---|
| arm0 (무학습) | **0.00%** [0.000, 0.012] | §0.1에서 **같은 가중치임이 검증된** `_env76_max512` |
| arm1 | **7.03%** [0.047, 0.104] | R11 |
| arm3 | **11.50%** [0.084, 0.155] | R11 |

arm0와 두 페르소나 arm의 구간이 **비중첩**이다. 문중 EOS는 여전히 학습된 성질이고
**결과**다 ⇒ **(B)는 발동하지 않는다.** 상·하한 쌍으로 되돌리지 않는다.

단, 절대값은 재학습 코호트의 15.3% / 27.8%보다 **작다**(7.03% / 11.50%). 서열과
비중첩은 유지되고 크기가 줄었다.

### 6.4 Gate 2 체크리스트 다섯째 항목 — 같은 체크포인트에서 처음 잰다

*"긴 상한에서 방향 유지 + 포함/제외 동시 제시"*. 사전등록된 항목이며 결과를 보고 만든
기준이 아니다. 거부율(`corrected_refused`):

| 셀 | 포함 @256 | 포함 @512 | 제외 @256 | 제외 @512 |
|---|---:|---:|---:|---:|
| arm1 / `none` | 0.9776 | **0.9776** | 0.9967 | 0.9935 |
| arm1 / `agreeable` | 0.6262 | **0.6262** | 0.8125 | **0.7101** |
| arm3 / `none` | 0.9840 | **0.9840** | 0.9968 | 0.9968 |
| arm3 / `agreeable` | 0.5974 | **0.5974** | 0.8455 | **0.7019** |

**절단 포함 값은 상한에 정확히 불변이다**(네 셀 모두 소수 넷째 자리까지 동일). 절단 제외
값은 순응 렌즈에서 **10~14포인트 움직인다.** 그리디 디코딩에서 상한을 올려도 거부 판정이
바뀌지 않기 때문이고, 제외는 상한이 정한 표본에서 응답을 **버리기** 때문이다.

⇒ 상한에 의존하는 쪽은 **제외 규약이다.** 이것은 §6.2가 (C)로 간 것과 모순되지 않는다 —
(C)는 `hit_cap` **자체의 크기**에 관한 판정이고, 이 표는 그 크기가 **헤드라인 결과값을
움직이지 않는다**는 별개의 사실이다. 그리고 이 표는 **코호트를 넘지 않는다.**

### 6.5 처분 — 무엇이 바뀌고 무엇이 서는가

| 원고(`paper/flmsec/main.tex` §`sec:cap`)의 문장 | R11 이후 |
|---|---|
| 재학습 공시 문단(*"That re-evaluation is a separate cohort…"*) | **같은 체크포인트 측정으로 대체 가능**하다. 더 짧고 더 강하다 |
| *"only 18 of 2,504 responses ($0.72\%$) actually reach the 512-token cap"* | 그 **코호트의** 값으로 범위를 좁힌다. 같은 체크포인트 4셀에서는 2.24% |
| *"Actually reaching the cap shows no such ordering over the same cells and is uniformly small: 1.6%, 1.28%, 0.96%, 0.32%"* | **서지 않는다.** 같은 체크포인트에서 arm0 1.6% < arm3 3.83% < arm1 5.11%로 **오히려 서열이 생긴다.** 이 문장은 걷는다 |
| 문중 EOS 15.3% / 27.8% (arm1 / arm3) | 서열·비중첩은 유지, 값은 7.03% / 11.50%로 재기술 |
| 헤드라인 규약(*included*) | **유지된다.** 근거가 §6.4로 바뀌고, 그 근거는 체크포인트 경계를 넘지 않는다 |
| 한계 문단(*"Two things bound this…"*) | (A)가 아니므로 **걷지 않는다.** 다만 내용이 바뀐다 — 경계는 이제 "다른 체크포인트"가 아니라 "512도 상한을 다 소진하지 못한다"이다 |

**Gate 2 상태**: 정의 네 조항이 R11 코호트(arm1·arm3 × `none`·`agreeable` × 시드42)에서
**전부 충족됐다**. 다만 헤드라인 격자는 4 arm × 4 렌즈 × 3시드이고 R11은 그 부분집합이다.
§2.4의 ⚠️대로 **격자를 이 코호트로 교체하지 않는다.** 상태표 갱신은 이 사실을 그대로 적는다.
